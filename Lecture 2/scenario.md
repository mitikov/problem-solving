# Вихідні дані лабораторної №2

Усі наведені репліки, числа та модулі створено для навчальної вправи. Позначення R — джерело, N — потреба, Q — вимога, T — тест. Не дописуйте до реплік вигаданих вимірювань.

## Шість реплік

| ID | Роль | Репліка |
| --- | --- | --- |
| R1 | Працівник | «Після обходу я працюю в іншому кабінеті й не бачу контейнер. Хочу повідомлення у телефоні» |
| R2 | Відвідувач | «Я дивлюся на червоний і зелений сигнали, але не розумію, що вони означають. Додайте напис» |
| R3 | Працівник | «Щоб замінити батарею, доводиться шукати викрутку. Хочу відкривати відсік без інструмента» |
| R4 | Адміністратор | «На навчальний прототип можу виділити не більше 800 грн» |
| R5 | Працівник | «Коли покази зникають, я не знаю, чи контейнер вільний, чи прилад не працює» |
| R6 | Відвідувач | «Коли залишаю предмет, хочу бачити актуальний стан, а не чекати невідомо скільки» |

Фрагменти для сортування: R1a/R1b — два речення R1; R2a/R2b — два речення R2; R3a/R3b — два речення R3; R4, R5, R6 — повні репліки. Категорії: спостереження/контекст; потреба/побажання; спосіб реалізації; обмеження. Виведена з контексту потреба записується окремо від дослівного фрагмента.

## Модель опитування

`T` — інтервал, с; `p = 0,2 с` — верхня оцінка оброблення; `D` — дозволена затримка. Стійка подія зберігається до наступного опитування. Опитування відбуваються точно кожні T секунд. Немає мережі, пропусків, джитеру й додаткового часу відображення. Для досліду тривалість оброблення взято рівною p.

Верхня оцінка затримки: `T + p`. Допустимість: `T + p ≤ D`. Частота: `1/T` Гц. Число опитувань за годину: приблизно `3600/T`; це оцінка частоти, не обіцянка цілої кількості для будь-яких кінців інтервалу.

Фаза `a` — частка T, що минула від попереднього опитування до події: у тренажері 1–99 %. Час від події до результату цього досліду: `(1 − a)T + p`. Зміна a не змінює верхньої оцінки. Додатний T можливий лише за `D > p ≥ 0`. Короткий імпульс між опитуваннями може бути пропущений; ця модель його виявлення не гарантує.

## Специфікація тестового стенда

- Вхід — відсоток заповнення. Придатні скінченні числа від 0 до 100 включно.
- За `fill_pct ≥ 85` потрібний стан **ПОВНИЙ**, за менших придатних значень — **Є МІСЦЕ**.
- Відсутній показ (`None` або порожній ввід), `NaN`, нескінченність, текст, логічне значення, число поза 0–100 дають **НЕВІДОМО**. Число у текстовому полі тренажера є способом введення числа, а не рядковим показом датчика; для нечислового рядка використайте `текст` або лапки.
- Стан має з’явитися **не пізніше ніж за 5 с** від початку стійкої події або стійкої непридатності входу, що доступна локальному опитуванню. Мережі й дій людини в цьому сценарії немає.
- Прототипи A–D створені для порога 85 %. Перемикач 90 % змінює **специфікацію стенда**, а не реалізації. Додатковий раунд демонструє необхідність переглядати тести та реалізацію після зміни вимоги.

Картки входів: `40`, `84`, `85`, `86`, `None`, `-1`, `101`, `NaN`. Додатково можна вводити `0`, `100`, `Infinity`, `true`, дробові числа та довільний текст. Крапка або кома дозволені як десятковий роздільник. Для часу незалежно від стану перевірте `4,9`, `5,0`, `5,1 с` у [ручному маршруті](manual-fallback.md).

## Методичні опори

Ці джерела пояснюють загальні принципи; вони **не встановлюють** пороги, ціни й репліки цього сценарію.

- [NASA — How to Write a Good Requirement](https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/): однозначність та перевірюваність вимоги.
- [W3C — Understanding Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): для вебконтенту колір не має бути єдиним способом передавання значення. У вправі з фізичним індикатором це аналогія принципу, а не твердження про його сертифікацію.
- [Python — math.isfinite](https://docs.python.org/3/library/math.html#math.isfinite): перевірка скінченності числа. Діапазон і поведінку за помилки визначає специфікація, а не ця функція.
