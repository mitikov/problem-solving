# Лабораторна №1. Розібрати незручність

До лекції **«Спочатку проблема: що саме ми покращуємо?»** курсу «Синтез технічних рішень».

Контейнер отримав індикатор, але предмети все одно опиняються поруч. Ваше завдання — з’ясувати, яку проблему варто розв’язувати, де проходить межа системи та яку перевірку зробити першою. Ще один датчик можна запропонувати пізніше, коли стане зрозуміло, навіщо він потрібний.

Це **одна індивідуальна лабораторна на 45 хвилин**, розділена на чотири файли. Викладач, напарник, реальне обладнання та платні підписки для виконання не потрібні. Усі картки, часові записи й моделі контейнера — **синтетичні навчальні матеріали**, а не результати польового дослідження.

## Підготовка — 3 хвилини

1. Збережіть [стартову дошку](lab-01-starter.drawio) та копію [шаблону звіту](report-template.md) на комп’ютер. На GitHub файл можна завантажити через **Download raw file**; якщо матеріали видані архівом, розпакуйте його.
2. Відкрийте [diagrams.net](https://app.diagrams.net/). Для місця збереження виберіть **Device / Пристрій**, якщо редактор запитає. Відкрийте дошку через **File → Open From → Device**. У ній уже є картки, шість вузлів і порожній причинний ланцюг. Вхід через Google або Microsoft не потрібний для цього способу роботи.
3. Збережіть власну копію через **File → Save as → Device** під назвою `lab-01.drawio`. У звіті замініть порожні поля своїми відповідями. Markdown необов’язковий: підходить звичайний текстовий документ із тими самими розділами.

Вкладки сторінок розташовані внизу diagrams.net. Перетягування змінює положення картки, подвійне клацання — її текст. Щоб зберегти версію перед зміною, натисніть правою кнопкою вкладку сторінки та виберіть **Duplicate**, потім **Rename**. [Відкривання файлів](https://www.drawio.com/docs/manual/open-diagram-file/), [робота зі сторінками](https://www.drawio.com/docs/manual/pages/) і [збереження на пристрій](https://www.drawio.com/docs/manual/storage-location-select/) описані в документації редактора.

## Що здати

- `lab-01.drawio`: картки; карти системи до й після зміни; причинні ланцюги до й після нового свідчення.
- `report.md` або текстовий документ: короткі пояснення за шаблоном, таблиця двох запусків LOOPY, паспорт проблеми й його оновлена версія. **Кожна версія паспорта — до 150 слів.**

За бажанням додайте скриншоти або посилання на змінену модель LOOPY. Вони допомагають відтворити роботу, але не замінюють пояснення. Обов’язкового відеозапису виконання немає.

Перед здаванням відкрийте збережений `.drawio` ще раз і переконайтеся, що всі версії залишилися у файлі. Дві хвилини наприкінці призначені саме для цього.

## Як перевіряється робота

| Частина | Що має бути видно у відповіді |
| --- | --- |
| 1 | Відмінність симптому, потреби й реалізації; проблема без передчасного вибору компонента |
| 2 | Обґрунтована межа, дві функціональні підсистеми, оточення, потоки трьох типів і зміна відповідальності |
| 3 | Різні пояснення, відокремлення даних від припущень, перегляд під впливом нового свідчення |
| 4 | Прогноз перед запуском, зміна одного зв’язку, межі висновку з моделі та перевірка, від якої залежить наступна дія |

Єдиного правильного розташування вузлів або тексту паспорта немає. Оцінюється обґрунтування. Обґрунтоване «даних недостатньо» краще за впевнене пояснення без свідчень. У кожному завданні є власний список самоперевірки та резервний спосіб роботи на випадок недоступності сайту.

## Зв’язок із лекцією та екзаменом

Послідовність відповідає блокам 1.1–1.4 [тематичного плану](../course-plan.md) та етапам А–Г [конспекту лекції](../Lecture_1_ProblemFraming_Definitions.md). Збережено картки А–Е, часові записи 12:00/13:00/14:00, нове свідчення про 13:02 і зміну умови «Wi-Fi недоступний». LOOPY додає коротку інтерактивну перевірку припущення до четвертого етапу.

- **Е01 з наданого плану:** завдання 1–2 — потреба, аналіз і синтез, межа системи, підсистеми й потоки.
- **Е02 з наданого плану:** завдання 3–4 — конкуруючі причини, свідчення, перша перевірка та наступний крок.

Окремого документа про офіційне затвердження екзаменаційного переліку не надано.

Формат адаптовано з [практичних завдань metrology-101, Lecture 4](https://github.com/mitikov/metrology-101/tree/main/Lecture%204): конкретні дії на сайті, прогноз, зміна умови, власний результат, коротке пояснення та чіткий перелік того, що здати. Пріоритет — наявні інтерактивні вебінструменти; програмування не є обов’язковим.
